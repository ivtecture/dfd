# Упрощённая копия Twitter: DFD и расчёт нагрузки

Домашняя работа по проектированию упрощённой копии Twitter: DFD-модель в Mermaid и
перевод целевых параметров в требования к инфраструктуре.

## Содержание

| Файл | Что внутри |
|:--|:--|
| [dfd.md](dfd.md) | 11 диаграмм: контекстная, уровень 0, декомпозиция всех семи процессов, компонентная диаграмма и диаграмма последовательности; словарь потоков, каталог хранилищ, проверка балансировки |
| [capacity.md](capacity.md) | Расчёт: целевые параметры → операции в сутки → интенсивность в секунду → трафик, хранилище, число узлов; сценарии чувствительности и сводные требования |

## Как читать

1. **Границы.** Начинать с [контекстной диаграммы](dfd.md) — она показывает, что вообще
   входит в упрощённую копию, а что вынесено наружу. Видео, трансляции, реклама, личные
   сообщения и рекомендательные ленты в систему **не входят**.
2. **Декомпозиция.** [Уровень 0](dfd.md) даёт семь процессов; каждый из них раскрыт на
   отдельной диаграмме (разделы 5–11 файла `dfd.md`).
3. **Связи.** [Компонентная диаграмма](dfd.md) переводит ту же модель в термины
   архитектуры, [диаграмма последовательности](dfd.md) объясняет, где возникает
   асинхронность.
4. **Словарь.** [Раздел 14](dfd.md) перечисляет все потоки с направлением, структурой и
   объёмом; [раздел 15](dfd.md) — хранилища с технологией и сроком хранения.
5. **Проверка.** [Раздел 16](dfd.md) сверяет внешние потоки родительской и дочерней
   диаграмм — балансировка DFD.
6. **Числа.** [capacity.md](capacity.md) переводит каждую операцию в сутки, каждую
   секунду, каждый байт и каждый узел. В конце — сводные требования и пределы модели.

## Три ключевых решения, на которых держатся все цифры

- **Гибридная раскрывка ленты.** Посты «обычных» авторов (95 %) раскрываются заранее при
  публикации, посты «громких» авторов (5 %, ≥ 1000 подписчиков) дозабираются при чтении.
  Это основной источник объёма кэша и операций слияния.
- **Пиковая нагрузка задаётся суточной.** Коэффициенты `2,88` (пиковый час) и `4,32`
  (всплеск) выведены из профиля суток, а не взяты «с потолка».
- **Медиа уходит через CDN.** Поэтому самый большой канал (69,5 Гбит/с) не проходит
  через origin (24,9 Гбит/с), а почти совпадает с суммарным внешним трафиком.
- **Узкое место — раскрытие ленты.** 37,6 млрд раскрытий в сутки против 833 млн запросов
  API: каждый API-запрос приходится 45 раскрышений, поэтому считать надо не запросы,
  а раскрытия и память под кэш.

## Диаграммы

Все диаграммы — код Mermaid внутри markdown, поэтому они отрисовываются **без
дополнительных инструментов** на GitHub и GitLab, а также в режиме предпросмотра
Markdown в VS Code и IntelliJ IDEA. Локально весь файл можно отрисовать в SVG одной
командой:

```
npx -p @mermaid-js/mermaid-cli mmdc -i twitter/dfd.md -o dfd.svg
```

Проверено: все 11 блоков разбираются парсером Mermaid 11 без ошибок.

## Конвенции

- Внешние сущности `E1 … E4`, хранилища `D1 … D9`, процессы `1 … 7` на верхних уровнях и
  `1.1`, `2.3` внутри декомпозиции.
- Внешние потоки `CF-01 … CF-14` одинаковы на всех уровнях и служат основой проверки
  балансировки; внутренние потоки `IF-01 … IF-14` появляются только на дочерних
  диаграммах.
- Цветовая кодировка: жёлтый — внешняя сущность, голубой — процесс, зелёный — хранилище,
  фиолетовый — соседний процесс (взаимодействие по «API»).
- Единицы измерения: `1 ТБ = 1024⁴ байт`, `1 ГБ = 1024³ байт`, `1 КБ = 1024 байта`.
